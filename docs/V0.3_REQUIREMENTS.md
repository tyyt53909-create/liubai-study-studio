> 本文件只定義「要做什麼、做到什麼程度、什麼不要做」；不是技術教程。

## 1. 文件定位

v0.2 已補足 Task History、私人登入、歷史資料邊界、Reminder 基礎可靠性及代碼拆分。v0.3 不再以工程完整度為主要目標，而以**降低每天使用摩擦**為核心。

本階段只授權直接提升日常學習流程的改動。不能因為工程上可以優化，就自動把低邊際項目提升為主線。

## 2. v0.3 核心目標

```text
想到要做
  ↓
快速記下
  ↓
安排 / 改期
  ↓
到點開始
  ↓
完成
  ↓
建立下一步
```

**核心衡量：是否讓使用者少輸入、少點擊、少重複設定、少忘記下一步，並更快開始真正學習。**

## 3. 必須維持的產品原則

| 原則 | 要求 |
| --- | --- |
| 使用者決策 | 系統不自動決定讀什麼、何時讀。 |
| Task-first | Calendar 仍只是 Task 的時間屬性，不把產品改成日曆軟體。 |
| 五種安排語義 | 保留 UNSCHEDULED / MONTH / WEEK / DAY / FIXED。 |
| Review 邊界 | Review 只表示記錄過的學習活動，不等於掌握度。 |
| 低輸入成本 | 任何新增欄位不得阻塞快速記錄。 |
| 安靜通知 | 未設定提醒或未啟用「到點提醒」時，不主動通知。 |
| 不遊戲化 | 不加入 streak、XP、排行榜、強制打卡。 |
| 不 AI 代決策 | 不加入 AI 自動排程、AI 弱項判定、AI 每日計劃。 |

## 4. P0 — Quick Capture

### 目標
想到一件事時，先把它記下來，不要求立即完成分類與估時。

### 必須行為
- Quick Capture 最低只要求 **Task title** 即可保存。
- Subject、Topic、預估時間、日期、Reminder、子項、備註均不得阻塞第一次保存。
- 未完成的分類或估時可以稍後在 Task Detail 補上。
- Quick Capture 必須在 Today 與 Task Pool 都能快速進入。
- 手機窄屏下仍需保持快速輸入，不要求展開完整表單。
- 完整「新增任務」表單可以保留，但不能成為唯一入口。

### 不做
- 不做自然語言 AI 解析。
- 不要求使用者在 Capture 階段決定 Month / Week / Day。
- 不因為資料欄位完整性而迫使用戶先填無關資訊。

## 5. P0 — 快速改期與重新安排

### 目標
臨時變更計劃時，不需要每次進入完整 Task Detail。

### 必須行為
未完成 Task 必須能從高頻頁面直接使用以下快速操作：

- 今天
- 明天
- 本週
- 下週
- 選擇日期
- 取消安排／回到未安排

要求：
- 「明天／本週／下週」這類高頻移動不應要求完整編輯流程。
- 改期後 Task History 必須繼續留下正確 PLAN_CHANGED。
- 已開始但未完成的 Task 仍可重新安排。
- 快速操作不得破壞 FIXED 與一般 DAY 的語義。

## 6. P0 — Fixed Time 與 Reminder 一體化

### 本階段採用的產品規則
當使用者把 Task 設為 `FIXED` 並指定時間時，同一流程內提供：

**「到這個時間提醒我」**

- 預設為開啟。
- 使用者可以關閉。
- 開啟時，Reminder 與 Fixed Time 使用同一時間，不要求再次輸入相同時間。
- Fixed Time 被改動時，與之連結的「到點提醒」同步更新。
- Fixed Time 被移除／改回非 FIXED 時，系統不得留下過時的連結提醒。
- 非 FIXED Task 仍可保留現有手動 Reminder 能力。

### 目標
消除「安排 20:00 → 再另外輸入 Reminder 20:00」的重複操作。

## 7. P0 — 完成後 Follow-up Task

### 目標
把「學習時發現下一個問題」立即轉成下一步，而不用重新建立整個任務。

### 必須行為
Task 完成後提供 **新增後續任務**。

新 Follow-up Task：
- 自動帶入原 Task 的 Subject。
- 有 Topic 時帶入 Topic。
- 不繼承完成狀態、Session、Review、Reminder、原安排。
- 標題由使用者輸入。
- 使用者可以立即保存到未安排，之後再安排。
- 此操作為可選，不得阻塞完成流程。

典型場景：

```text
完成：Biology Genetics Past Paper
發現：Q4、Q7 要重做
→ 新增後續任務
→ Redo Q4, Q7
```

## 8. P1 — Do Again

### 目標
降低重複學習任務的建立成本。

### 必須行為
在已完成 Task / History 中提供 **再做一次**。

新 Task：
- 是獨立的新 Task。
- 可繼承 title、Subject、Topic、estimated、is_review。
- 不繼承 Session、完成時間、Task Event、Reminder、Plan。
- 預設回到未安排。
- 原 Task 歷史完全保持不變。

不建立 Habit System，不加入連續打卡。

## 9. P1 — Today 作為執行台

### 目標
Today 的第一任務是讓使用者快速知道「現在做什麼」並開始，而不是展示更多統計。

### 必須行為
- Today 首屏優先呈現：目前 active Task、今天 Task、未安排的少量入口。
- 已安排 Task 的主要操作應優先是 Start / Continue。
- 常用 Move 操作應可從 Today 直接使用。
- Active Session 保持全局可見。
- Capacity / Time Ring 可以保留，但不得壓過「今天要做什麼」與「開始」的主層級。
- 不新增 KPI 卡片、streak、效率分數或額外 dashboard。

## 10. P1 — Reminder 到執行的最短路徑

已有 Notification deep link 必須保留。提醒到達後，使用者應能快速完成以下任一操作：

- Start / Continue
- 延後 30 分鐘
- 移到明天

不要求本階段一定使用 OS notification action button；但從通知進入 Task 後，高頻操作不得再埋在多層設定中。

## 11. 搜尋與歷史：本階段只修阻塞使用的問題

History / Task Event 是 v0.2 已完成能力，本階段不擴張成分析平台。

必須修正：
- 已完成／已取消 Task 的搜尋不能只搜尋目前分頁；當使用者主動搜尋歷史任務時，結果需要涵蓋完整可查歷史。

本階段不做：
- 複雜統計報表。
- 任務生產力評分。
- 自動弱項分析。
- 大型數據 Dashboard。

## 13. Exam 的位置

Exam 是產品高價值方向，但**本文件不授權 Codex 直接實作完整 Exam System**。

下一階段討論時，優先探索：

```text
Exam / Context
  ↓
一組既有 Task
```

而不是另一套 Todo、AI 複習計劃或複雜 syllabus 系統。

在 v0.3 的 P0 / P1 日常流程完成並開始真實使用之前，不因「還有時間」自行加入 Exam。

## 14. 驗收標準

### A. Quick Capture
- 只輸入 Task title 可以成功保存。
- Subject / Estimate 未填不阻塞 Capture。
- 保存後任務可在 Task Pool 找到。
- 後續可以補齊分類與估時。
- 真人目標：想到任務後約 5 秒內可完成記錄；自動化測試不可替代真人驗收。

### B. Quick Reschedule
- 未完成 Task 可在不進完整編輯頁的情況下移到明天、本週、下週或未安排。
- 改期後 History 只生成正確且必要的 PLAN_CHANGED。
- 沒有實際變更時不生成無意義事件。

### C. Fixed + Reminder
- 設定 FIXED 20:00 並保持「到點提醒」開啟，只輸入一次 20:00。
- 改成 20:30 後連結提醒同步到 20:30。
- 關閉「到點提醒」後不通知。
- 移除 FIXED 後不留下舊的連結提醒。

### D. Follow-up
- 完成 Task 後可一個流程建立後續 Task。
- Subject / Topic 正確帶入。
- 新 Task 不繼承舊 Session、Plan、Reminder 或完成狀態。
- 不建立 Follow-up 也能正常完成原任務。

### E. Do Again
- 從完成 Task 建立新的獨立 Task。
- 原 Task 歷史不變。
- 新 Task 為未完成、未安排、無舊 Session / Reminder。

### F. Today
- 有今日任務時，進入 Today 可以明確看見可開始的 Task。
- 開始／繼續是主要操作。
- 快速改期不需要多層設定。
- Active Session 行為保持原有正確性。

### G. Reminder → Action
- 點通知仍可定位對應 Task。
- 進入後能直接 Start / Continue。
- 能快速延後 30 分鐘或移到明天。

### H. History Search
- 歷史完成任務超過一頁時，搜尋仍能找到不在第一頁的符合 Task。

## 15. 回歸要求

以下 v0.2 行為不得被 v0.3 破壞：

- UNSCHEDULED / MONTH / WEEK / DAY / FIXED 五種語義。
- 單一 active session。
- Pause 不計時。
- Stop 保存 IN_PROGRESS，Continue 可延續。
- 實際時間與剩餘估時正確。
- Task Event 不可變。
- completed_at / cancelled_at 正確。
- Review 與 Task Event 保持獨立。
- History 分頁與長期資料邊界保持。
- 私人登入與未授權 API 保護保持。
- Reminder 只在使用者設定／啟用的情況下通知。
- 390px 與桌面版核心流程可用。
